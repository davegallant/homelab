# Invidious on the Talos cluster (Argo CD)

Invidious runs from the bjw-s **app-template** chart (5.3.0) as an
Argo CD Application — no local chart. Desired state is
`values.production.yaml` in this directory; the Application
definition is `../argocd/applications/invidious.yaml`. Syncs are
manual, pruning is off, and deleting the Application preserves the
workload.

Workload definition: `values.production.yaml`. The migrated LXC
Compose stack and its Ansible playbook have been retired.
(app `quay.io/invidious/invidious:2026.10.23-4a271da`, port 3000;
companion `quay.io/invidious/invidious-companion:2026.10.18-fcb0456`,
port 8282; database `docker.io/postgres:18.6` — all three in one pod
here, where the compose ran them as separate services).

Exposure is **public via Pangolin** — the retired LXC paired the app
with a Newt sidecar, reproduced in-pod with the *same* Newt identity,
so the existing Pangolin route and public URL carry over unchanged.
Do not rewrite this app as tailnet-only.
Expect a brief public outage at cutover while the Newt identity
moves from the LXC to the pod.

State is the Postgres database (users, subscriptions, history,
preferences). It moves by logical dump/restore at cutover (the
Miniflux pattern), never by copying the Postgres data directory.
In the values, `db-data` is a chart-managed local-path PVC (5Gi)
mounted by the `db` container at `/var/lib/postgresql`. After
cutover, bind the data through a repo-managed static local PV and
claim (a `db-data-local-pv.yaml` beside this README, using the
dynamic claim's provisioned path and node), switch the values to the
`db-data-local` claim for the live mount, and keep the original
claim mounted read-only at `/mnt/invidious-rollback-db-data` — the
Batch A/B post-cutover shape.

The companion's cache (`companion-cache`, 1Gi) is **not** copied —
it holds youtubei.js signature state that the companion rebuilds on
its own; expect the first hours after cutover to be slightly slower
while it warms. The companion keeps the compose's hardening
(read-only root filesystem, all capabilities dropped).

The whole `INVIDIOUS_CONFIG` block is generated by the secret
playbook into the `invidious-external` Secret, with the database and
companion hosts rewritten to `127.0.0.1` (neighbouring containers).
Secrets stay in Vault and outside Argo's ownership, both created by
`playbooks/talos-cluster/invidious-secret.yml`:
`invidious-newt-external` (Pangolin/Newt) and `invidious-external`
(`INVIDIOUS_CONFIG`, `SERVER_SECRET_KEY`, `POSTGRES_USER`,
`POSTGRES_PASSWORD`).

Backups: Velero Schedule `invidious-daily` (in the values) with pod
annotation `backup.velero.io/backup-volumes: db-data-local` and a
pre-backup hook that writes a `pg_dump` into the volume, so the
filesystem backup carries a restorable copy. The network policy is
the house default-deny CiliumNetworkPolicy, in the values as
`rawResources.defaultDenyNetworkPolicy` — world egress is
load-bearing here (YouTube), as it is for Newt.

## Prerequisites (once)

1. `apps/argocd/project.yaml` updated (invidious destination) and
   applied via `playbooks/talos-cluster/argocd-project.yml`.
2. Namespace: `kubectl --context admin@homelab apply -f kubernetes/apps/invidious/storage.yaml`
3. Secrets: run `playbooks/talos-cluster/invidious-secret.yml`. Its
   asserts name every Vault key it needs (`invidious_db_user`,
   `invidious_db_password`, `invidious_companion_secret_key`,
   `invidious_hmac_key`, `invidious_newt_id`, `invidious_newt_secret`,
   `pangolin_endpoint`); a failed assert means the Vault spelling
   differs — fix the playbook, not the Vault.

## Staging

Values ship with `replicas: 0`. Commit, push, register the
Application, approve the first Sync — objects and PVCs appear, no
pod starts, the LXC keeps serving:

```sh
kubectl --context admin@homelab apply -f kubernetes/apps/argocd/applications/invidious.yaml
```

## Cutover

1. With the LXC stack still running, capture the source counts and
   take the dump (user/password per the compose's `POSTGRES_USER` /
   `POSTGRES_PASSWORD`):

   ```sh
   ssh root@invidious 'docker exec invidious-db psql -U <db-user> -d invidious -Atc "select count(*) from users; select count(*) from videos;"'
   ssh root@invidious 'docker exec invidious-db pg_dump -U <db-user> invidious' > /tmp/invidious.sql
   ```

2. Stop the LXC stack (drops the public route until step 5):

   ```sh
   ssh root@invidious 'cd ~ && docker compose down'
   ```

3. The gate for continuing: a complete dump file from step 1 and
   its counts recorded. A truncated or empty dump means stop here,
   restart the LXC stack, and report.
4. Restore into the cluster: start a one-shot Postgres pod mounting
   the `invidious-db-data` claim (confirm the claim name with
   `kubectl -n invidious get pvc`), let it initialise an empty
   database, load the dump with `psql`, then delete the pod. Verify
   the step-1 counts match in the cluster database before
   continuing. Mismatch → debug and re-restore; if it will not
   verify, restart the LXC stack, leave Invidious serving there,
   and report.
5. Bind the static local PV (above), remove `replicas: 0` from the
   values, commit, push, approve Sync.
6. Verify: pod `4/4` Ready; the public Invidious URL loads; play a
   video end-to-end (this exercises the companion, not just the app
   — the dashboard alone proves nothing); log in and confirm
   subscriptions/history survived. Argo Synced/Healthy. Create and
   verify a Velero backup with its `db-data-local` PodVolumeBackup (the
   script in the Navidrome README, with schedule `invidious-daily`
   and volume `db-data-local`).
7. Leave the stopped LXC as rollback target until soak completes.

Rollback: `docker compose up -d` on the LXC (its Newt sidecar
re-registers the public route); bring the cluster pod down via a
`replicas: 0` commit + Sync so the Newt identity is not claimed
twice.
